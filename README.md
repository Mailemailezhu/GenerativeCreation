# GC — GenerativeCreation

本地 AI 图像创作工作台：ComfyUI 引擎 + PyQt5 画布，面向 Lightroom Classic 修图后的局部生成式创作。

## 目录

| 路径 | 说明 |
|---|---|
| `app/` | PyQt5 界面，独立虚拟环境 `app/venv` |
| `app/core/` | ComfyUI 客户端、局部重绘管线、模型目录、内存解码、导出 |
| `engine/` | ComfyUI 引擎（submodule），独立虚拟环境 `engine/venv` |
| `models/` | 模型文件，不入库，由 `config/extra_model_paths.yaml` 挂载 |
| `config/` | 引擎与软件配置（`hints.xml` 界面文案、`ui.json` 缩放字号；`api_models.json` 含密钥，不入库） |
| `scripts/` | 启动脚本、冒烟脚本、本地 mock 接口 |
| `data/` | 运行数据（引擎日志、自检截图），图像不在这里缓存 |

## 环境

- Python 3.12（uv 管理，两个独立 venv，不碰系统 Python）
- PyTorch 2.9.1+cu130（RTX 5070 / sm_120；cu128 构建会打印性能警告）
- ComfyUI 0.45.0 + ComfyUI-GGUF

## 启动

1. 界面：`app/venv/Scripts/python.exe app/main.py`，或双击项目根目录的 `GC.lnk`（打包版）
2. 引擎：不用手动开。第一次点「生成预览图」时程序自己拉起 `engine/venv` 里的 ComfyUI
   （监听 127.0.0.1:8188，`--fast-disk` 让权重从 NVMe 流式加载，约 40 秒起好），
   日志写到 `data/engine.log`。想提前预热可以走「文件 → 启动本地引擎」，或运行 `scripts/start-engine.ps1`。

## 界面缩放

程序自己接管缩放，默认 125% / 14 px（100% = 1:1 物理像素，不跟随系统 DPI），所以 2K 屏 + 175% 不会把窗口和每个控件再放大一遍。

- `选项 → 界面缩放`：100 / 125 / 150 / 175%，写进 `config/ui.json`，重启生效；末项一键回默认 125%
- `选项 → 字体大小`：11 / 12 / 13 / 14 / 16 / 18 px，改完立刻生效（只重刷样式表）

缩放必须在 `app/bootstrap.py` 里设：Qt 加载平台插件时已经读过 `QT_SCALE_FACTOR`，
等到 `main()` 里再设就没用了；同时不能开 `AA_EnableHighDpiScaling`，否则它会在系统 175% 上再乘一次。

## 提示文案

界面上的所有悬停提示、参数说明都放在 `config/hints.xml`，改文案不用碰代码：

- `<tips>`：参数说明（步数、CFG、融合强度、羽化、种子、素材、规范化…）
- `<ui>`：控件提示（硬度、不透明度、容差、模型头、高级设置、素材「+」等）
- `<tools>` / `<views>`：左栏工具与底部对照按钮的名称、描述；**节点顺序就是界面顺序**

删掉某一条会回落到 `app/core/hints.py` 里的默认值；删掉整个文件软件照常启动。
改了默认文案想重新生成模板：`app/venv/Scripts/python.exe scripts/make_hints_xml.py`。

## 打包版

`scripts/build-release.ps1` 用 PyInstaller 打成 `dist/GC/GC.exe`（onedir），并生成：

- `GC.lnk`：项目根目录的快捷方式，工作目录指向项目根，所以 `models/`、`workflows/`、`config/` 都按相对路径找到
- `release/GC-<版本>-windows-x64.zip`：不含模型（体积太大），解压到项目根旁边即可复用同一套 `models/`

自检：`dist/GC/GC.exe --selftest` 会在 `data/_selftest.png` 截图并写 `data/_selftest.txt`，
用来确认打包后资源路径没断。

## 从 LrC 启动

LrC 15.1 的「编辑于 → 在外部编辑器中打开」格式下拉只有 TIFF / PSD / JPEG，没有 PNG。
推荐 **TIFF（8 位 / sRGB）**：程序直接把它解成 8 位 RGB 放在内存里给画布用，不落缓存文件，
关掉程序就没了；之后按 **同名 PNG → 同名 JPEG** 兜底查找。
结果不写回 LrC，成品只走「导出为…」。

## 选区工具

工具栏照着 PS 排：

| 工具 | 键 | 用法 |
| --- | --- | --- |
| 画笔蒙版 | B | 涂抹要重新生成的范围；大小 / 硬度 / 不透明度可用 |
| 橡皮 | E | 擦掉涂过的蒙版 |
| 矩形选框 | M | 拖出矩形直接加入选区 |
| 魔棒 | W | 点一下选中颜色相近的连续区域，容差 1–255 |
| 快速选择 | Q | 按住拖动，只吸附按下时那种颜色 |
| 指针 | H | 左键拖动画面（空格或中键也行） |
| 缩放 | Z | 点击放大，Alt+点击缩小，滚轮以鼠标为中心；选项栏会出现「放大 / 缩小 / 适应窗口」 |

工具按钮排在左侧竖栏（单列图标，宽 46 px，跟 PS 的工具条一样窄；悬停出名称、快捷键与用法），
竖栏底部是「原图 / 对比 / 预览」和分割方向 ⇄/⇅，
没有预览图时这一组是灰的。竖栏用的是无框 `QDockWidget` 而不是 `QToolBar`：竖向工具栏只按
`sizeHint` 给高度，底部那组按钮贴不到窗口底边。

指针和缩放时画笔参数会自动收起，选项栏只剩选区信息和缩放按钮。
参数栏里的三个滑块是伸缩宽度（最小 80 px），窗口变大或界面缩放变化时按比例变长，
不会像固定像素宽度那样把整行顶出去。
模式「添加 / 减去」对所有选区工具生效；「羽化选区」对现有蒙版整体软化，Ctrl+Z / Ctrl+Y 撤销重做。
蒙版以 Alpha 通道在内存里转成灰度图，编码成 PNG 字节后直接上传引擎，不写中间文件。

## 生成

- 「生成预览图」：草稿档，长边由按钮内齿轮决定（默认原图 10%，限制 256–2048），4 步，约 20 秒
- 「应用预览并生成正式图」：原图 + 草稿 + 素材（≤2048 长边）三参考图重绘，约 90 秒
- 只回贴画笔蒙版形状内的像素，蒙版外逐位不变；羽化环由蒙版外扩+高斯生成，边缘过渡自然
- 原图、预览图、正式图、裁剪块、蒙版、素材拼图全在内存里传递（`core/cache.py` 只负责解码），
  运行目录不再出现 `data/cache`、`data/_gc_tmp`、`data/_gc_mask.png`；老版本留下的启动时自动删
- 引擎的 `output/` 只当传输通道：取回字节后立刻删掉那一张，启动时再清一次历史残留（远程 API 不碰）
- 「复位图像」在生成按钮下方：丢掉预览和正式图，回到刚打开的原始图像，蒙版一起清空

所有会改生成结果的数字都收在面板的「高级设置」折叠块里（默认折叠，其余部分照样滚动）：

| 项 | 默认 | 作用 |
| --- | --- | --- |
| 融合强度 | 1.00（0.30–1.00） | 正式图在蒙版内重画时保留原图的程度。1.0 完全重画，造型最自由但与周围风格容易分裂；0.6–0.8 保留原片颗粒与光线，融得更自然。草稿档恒为 1.0 |
| 羽化 | 自动（0–80 px） | 贴回时边缘的过渡宽度，自动 = 选区短边的 6%。太大把周围原图也抹模糊，太小会看到硬边；24 MP 一般 10–16 |
| 步数 | 4 | 采样轮数。配的是 4 步加速 LoRA，改成 20 步只会更慢，不一定更好 |
| CFG | 1.0 | 提示词服从度。加速 LoRA 在 1.0 附近工作，调高容易出过曝或画崩 |
| 种子 | 随机 | 固定数字可复现同一张结果；微调时先记下它 |
| 调色 | 开 | 贴回前把生成片段的 LAB 均值/方差对齐到蒙版外的原图，关掉颜色更贴提示词但容易跳色 |
| 锁构图 | 关闭（0.00–0.90） | 正式图的初始 latent 换成「放大后的预览草稿」而不是原图，只重渲染细节、不再重新构图。0.50–0.60 几乎完全跟草稿走；0.70 起允许补细节，可能多出元素。关闭时草稿只当风格参考 |

## 对照

预览图不再弹独立窗口，直接贴回画布做原图 / 预览对照（同 LrC 的参考视图）：

- 左侧竖栏底部「原图 / 对比 / 预览」三个按钮，或「视图 → 查看」（Ctrl+Alt+0/1/2/3）
- 再点一次已选中的那个按钮 = 取消对照，回到只编辑蒙版（不显示对比效果）
- 对比模式下中间有一条线，拖动它改两侧占比；点 ⇄ / ⇅ 换左右或上下分割（Ctrl+Alt+X）
- 分割线中点有个蓝色圆点，鼠标靠近时指针会变成左右 / 上下箭头

## 模型

右侧列表只显示已安装的本地模型和已配置的 API 方案。
「＋ 添加模型」会读取本机显存与内存，列出这台机器能直接跑的档位并一键下载
（每档 = GGUF 主模型 + text encoder + VAE，Qwen 档位另带 Lightning 加速 LoRA）。

本地有两族，切换时步数/引导强度默认值、正式档尺寸、工作流一起换：

| 族 | 工作流 | 默认步数 | 正式档长边 | 素材图 | 说明 |
|---|---|---|---|---|---|
| Qwen-Image-Edit-2511 | `workflows/qwen_edit_2511_inpaint.json` | 4（Lightning LoRA） | 2048 | 支持（最多三张参考） | 会认提示词里的物体、能接素材；KF 采样快 |
| FLUX.1-Fill-dev | `workflows/flux_fill_inpaint.json` | 20 | 1536 | 不支持 | 专用修补模型，蒙版边缘融合更自然；只认英文，慢一倍 |

FLUX 的 CFG 固定 1.0（蒸馏模型），引导强度走 `FluxGuidance`（默认 30）；素材图和锁构图对它无意义，选中时自动禁用。
两族的 crop/蒙版/贴回/导出逻辑完全共用，只有采样节点链不同。

## API 方案

列表最后一行「＋ API 方案…」打开配置页：名称 / 接口地址 / 模型 / API Key，
「测试连接」用 `GET {base}/models` 探活（鉴权、延迟、可用模型一起验证）。
应用后该方案即成为当前模型，生成改走 `POST {base}/images/edits`（原图 + 蒙版 + 提示词），
返回图缩回 crop 尺寸后走同一套色彩对齐与贴回逻辑。
### 锁构图

默认正式档是「原图 + 草稿 + 素材」三张参考、denoise 1.0 全重画，构图和数量可能和预览不同——
实测同一个蒙版，预览画布 488×600 出 3 架纸飞机，正式档 1672×2048 出 10 架，数量是被画布像素决定的。

「锁构图」改成把预览草稿按比例裁出同一块、放大到正式尺寸、VAE 编码后当初始 latent，再从中等 denoise 细化：

| 设置 | 实测（976×1200，4 步 Lightning，52 秒） |
|------|------|
| 0.55 | 两架纸飞机位置与草稿完全一致，边缘和尾迹比草稿干净，蒙版内高频能量 2.12（草稿 2.17） |
| 0.70 | 原有两架保留，右侧额外多出三架 |

注意两点：
- 直接降「融合强度」不会锁构图。初始 latent 仍是原图时，denoise 0.5–0.7 只会把蒙版内洗成一片雾（实测高频能量 0.78、纸飞机整片消失），因为模型没机会重画新内容。必须走锁构图这条路径。
- 锁构图会把草稿的缺点一并继承下来，只是细节重新渲染；草稿本身构图不对时应该重出预览，而不是靠正式档去救。

选中 API 方案时步数 / CFG / 融合强度 / 锁构图 / 素材图自动禁用——远程接口不接受这些参数。
密钥只存本地 `config/api_models.json`，该文件已加入 `.gitignore`。

## 导出

文件 → 导出为…（`Ctrl+Shift+E`），Adobe 式左侧预览 + 右侧设置：

| 格式 | 质量选项 |
|---|---|
| JPEG | 品质 0–12（8 以上走 4:4:4 采样）、渐进式 |
| PNG | 压缩 无 / 低 / 中 / 高（无损，只影响写入时间与体积） |
| TIFF | 压缩 无 / LZW / ZIP |
| PSD | 无质量选项；写合成图 + 两个图层：「原始图」在底，「生成内容」按蒙版带透明度 |

只写 8 位：源图本身是 8 位 PNG，ComfyUI 内部也是 8 位，补 16 位只是把字节数翻倍。
对话框里的「预估大小」是真编码一次得到的精确值，不是经验公式（PSD 例外，它是按图层写的，
估算没意义，直接显示「—」）。

### PSD 图层

Pillow 写不了分层 PSD，`psd-tools` 只读，`pytoshop` 没有 Python 3.12 的轮子，所以
`app/core/psd.py` 按 Adobe 文件格式规范手写了最小写入器：头部 → 颜色模式 → 图像资源 →
图层信息 → 合成图，通道数据逐行 PackBits 压缩。图层名同时写 Pascal 串和 `luni`（UTF-16BE）
块，中文名在 PS 里才不会变乱码。

导出的 PSD 在 PS / Affinity 里是底部「原始图」（完全不透明）+ 顶部「生成内容」（Alpha 来自
画布上的蒙版，含画笔软硬和不透明度）。PS 里关掉上层就是没做过创作的原始照片，改上层的不透明度
或混合模式就等于调融合效果——不用重新生成。合成图（不看图层时的预览）与实际画面逐像素一致。
